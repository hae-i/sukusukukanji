- Dart 포맷, Flutter 정적 분석
- 기존 콘텐츠 파싱/validation/레슨 순서 및 optional 필드 테스트
- 5자/8문제 생성, 3종 유형, 검증 데이터 기반 선택지, 다른 유효 읽기 제외
- 중복 응답 차단, 저장 실패 후 같은 완료 객체로 재시도
- 오답/정답 누적, 복습 2회 성공·중간 실패, 수동 복습 추가
- 같은 날·다음 날·날짜 공백·과거로 이동한 시계의 streak
- **실제 SQLite 임시 파일** 생성→커밋→닫기→다시 열기. 모든 진행 필드·졸업 확인 복원
- 중간 SQL 제약 오류 시 트랜잭션 롤백, 재시도, 세션 ID 중복 방지, 동시 쓰기의 갱신 보존
- 제품 `AppController` + 실제 SQLite 저장소를 함께 구성해 학습→재생성→다음 레슨→오답 복습→재생성을 검증
- preferences adapter는 테스트용 API 대역으로 직렬화/복원/손상/실패 처리를 검증. OS의 실제 preferences 채널은 기기 검증 대상
- 위젯 테스트에서 온보딩→5카드→8문제→결과→홈→앱 위젯 재생성→복습 2회를 실제 탭으로 진행
- 나가기 확인/종료, 온보딩 저장 실패, 학습 저장 실패, 상세에서 복습 추가, 필터
- 학년 완료→결과 닫기→축하→확인 저장→재생성 후 축하 반복 없음
- 320px 화면/글씨 2배 기본 화면 레이아웃 및 한자 카드의 접근성 탭 액션

Phase 6 구현 후 정적 분석과 전체 54개 테스트를 통과한 다음 Phase 7의 80자를 연결했습니다. 최종 72개 테스트에는 공식 80자 목록 대조, 16개 레슨 완료 후 실제 SQLite 파일 재열기, 졸업·진급·오답 유지·아이콘 보상과 확인 상태 복원이 포함됩니다.

10자 테스트 전용 과정은 화면 흐름을 빠르게 검증하기 위해 유지합니다. 별도로 실제 80자 과정의 졸업을 검증하며, 10자만 학습해도 졸업하지 못하는 테스트도 유지합니다. 제품에 졸업 우회 기능은 없습니다.

- 아이콘 해금 후 자동 선택 변경 없음, 잠긴 아이콘 선택 차단
- 기기 변경 실패 시 이전 선택 보존, preferences 저장 실패 시 서비스의 이전 기기 아이콘 복원 (테스트 서비스 사용)
- 확인한 해금 모달 재실행 시 반복하지 않음, ‘나중에’는 선택을 바꾸지 않음
- 320px/글씨 2배의 아이콘 화면 및 해금 모달 레이아웃, 저장 지원 여부 안내
- 전체 80자에서 여러 난수 seed로 유효한 다른 읽기 및 같은 원문 뜻을 가진 한자의 뜻을 오답으로 내지 않는지 확인
- 식물 아이콘 생성 도구를 별도로 실행해 PNG 6개 생성 성공 (전체 72개 회귀 테스트 수에는 포함하지 않음)
- `flutter build bundle --target-platform=linux-x64 --debug --no-pub` 성공: Dart kernel 및 정적 assets 번들 생성

실행 명령과 클라우드 캐시/통계 설정은 [README](../README.md)에 있습니다. 테스트 대역은 `test/`에만 있습니다. 제품 앱은 항상 SQLite와 플랫폼 preferences를 사용합니다.

## 설치 가능한 환경에서 남은 확인

이 클라우드에는 Android SDK/에뮬레이터와 macOS/Xcode가 없습니다. 기본 Android 대상 번들 빌드는 native build hook에서 SDK 부재로 중단됩니다. `--target-platform=linux-x64`로 Dart 코드와 assets의 디버그 번들을 검증하며, APK/IPA와 네이티브 플러그인의 실제 기기 동작을 확인한 것은 아닙니다.

1. `flutter run`으로 Android/iOS 실행, 최초 온보딩과 한/일 글꼴 확인.
2. 5자 학습 후 일부 오답을 내고 결과→홈의 5/80과 복습 버튼 확인.
3. 앱 강제 종료/재실행: 온보딩 생략, 5/80·오답 상태 복원 확인.
4. 같은 한자 복습을 2회 모두 맞혀 복습 해제 확인. 중간 오답 시 연속 성공 초기화 확인.
5. 미완료 카드/퀴즈에서 종료 시 새 학습이 기록되지 않고 앞서 완료한 기록이 보존되는지 확인.
6. 배운 한자·헷갈리는 한자 필터, 수동 복습 추가, OS 화면 읽기 도구와 큰 글씨 점검.
7. 80자 학습 후 졸업·다음 학년 준비 중·아이콘 해금·확인 후 재실행 검증.
8. **아직 구현하지 않은 OS 아이콘 변경:** Android alias/iOS alternate icon 리소스 등록과 `sukusukukanji/app_icon` 네이티브 핸들러 연결. 지원 여부·현재 아이콘·변경 계약은 Dart에 있으며, 현재는 기기 변경 대신 선택만 저장하고 이를 알림. 실제 런처 캐시·실패 복구·iOS 시스템 알림을 기기에서 확인.

앱 삭제/OS의 저장 공간 삭제는 local-first 기록을 제거할 수 있습니다. 현재 백업·로그인은 제공하지 않습니다.

## 번들 폰트·반응형 그리드 검증

Noto Sans JP와 Pretendard를 FontLoader로 직접 로드한 테스트를 추가했습니다. 음독/훈독이 같은 높이에 배치되며 320px/글씨 2배에서 overflow가 없고, 320·390·430·600px의 첫/마지막 그리드 카드가 양쪽 경계에 맞으며 정사각형인지 확인합니다. 새 한자 상태 텍스트 제거, 학습 체크/복습 빨간 X, 홈의 연속일 위치와 한국어 글꼴도 확인합니다. 원본 폰트의 한자/한글 glyph coverage 및 licence를 확인했습니다.


## 학습 탭·예문·글꼴 범위 검증

학습 탭 첫 진입과 다른 탭에서 돌아올 때 7번 레슨이 화면 상단에 들어오는지 확인합니다. 홈·학습·내 한자·상세·설정 경로의 실제 RichText 스타일에서 Noto Sans JP/Pretendard와 앱바 볼드가 유지되는지 검증합니다. 복습 버튼의 연한 배경, 퀴즈 피드백 배경·테두리·그림자도 검증합니다. 기본 글씨에서 3열, 글씨 2배에서 2열을 사용하며 기존 폭별 정사각형·양쪽 경계 테스트를 유지합니다.

1학년 77자의 예문 출처·해당 한자 포함·한국어 번역·라이선스·확인 이력과 전사 마크업 제거를 검사합니다. 출처 누락·잘못된 라이선스의 JSON 파싱 실패, 예문 누락 허용과 320px/글씨 2배에서 긴 예문·출처 정보 팝업의 레이아웃도 확인합니다. 전체 72개 테스트를 통과했습니다. `dart format .`, `flutter analyze --no-pub`, `flutter test --no-pub`, `flutter build bundle --target-platform=linux-x64 --debug --no-pub`로 검증합니다.

남은 콘텐츠 작업: 村·森·糸의 적절한 예문·한국어 번역 출처 확보와 출시 전 교육 전문가 검수. 이번 작업은 2학년 이상 콘텐츠를 연결하지 않습니다.


## 여백·통합 출처·팝업 글꼴 업데이트

홈의 연속일 아래 간격과 학습 학년 제목 아래 간격을 줄이고, 오늘의 학습 보조 문구를 제거했습니다. 내 한자에서는 한글을 카드 하단에 고정하고 한자와 간격을 둡니다. 카드 진행 문구는 ‘오늘의 한자 n / 5’이며 아래에 여백을 추가했습니다.

출처는 카드 하단에서 제거하고 학습·상세 앱바의 ⓘ 아이콘에서 함께 확인합니다. 스와이프 후 현재 한자의 사전 및 예문 출처가 열리는지, 320px/글씨 2배에서도 출처 팝업에 overflow가 없는지 검증했습니다. 기존 흐름 테스트에서 나가기 팝업 제목의 Pretendard/볼드 및 본문 Pretendard도 실제 RichText 스타일로 확인합니다. 전체 72개 테스트와 정적 분석을 통과했습니다.

히라가나가 없는 예문은 19개 한자 카드에 있으며, 月의 수집 원본에는 자동 생성된 미검토 전사만 있었습니다. 예문은 계속 표시하되 검토되지 않은 읽기는 생략하는 기존 콘텐츠 정책을 유지합니다.


## 전역 글꼴과 혼합 문장

Pretendard 지정은 전역 테마 한 곳으로 통합했습니다. 한국어 버튼·탭·앱바·팝업은 전역 textTheme에서 스타일을 가져옵니다. 한글과 일본어가 섞인 문장은 TextSpan으로 일본어 문자 구간에만 Noto Sans JP를 지정합니다. 한글, 가나, 한자 및 보충 평면 한자가 섞인 텍스트의 실제 RichText 트리를 검사해 원문 유지와 언어별 적용 폰트를 확인했습니다. 기존 전체 화면·팝업 글꼴 및 큰 글씨 레이아웃 검증을 포함해 전체 73개 테스트와 정적 분석을 통과했습니다.


## 화면 하단 퀴즈 피드백

320×568 화면에서 기본/2배 글씨로 정답과 오답을 선택합니다. 피드백 패널이 퀴즈 화면의 하단 경계에 맞고 보기와 겹쳐 표시되는지, 페이지를 추가로 스크롤하지 않아도 다음 버튼을 바로 누를 수 있는지 검사합니다. 다음 문제에서 피드백이 닫히고 문제 번호가 증가하는지와 레이아웃 overflow가 없는지도 검증합니다. 기존 온보딩·학습·퀴즈·결과·저장·복습 시나리오를 포함해 전체 75개 테스트를 통과했습니다. 따라쓰기·손글씨 채점 기능은 구현하지 않았습니다.


## 퀴즈 패널 하단과 애니메이션

퀴즈에서는 패널 배경이 화면 하단 끝까지 이어지고, 시스템 제스처 영역의 여백은 패널 내부에서 버튼을 보호합니다. 질문 영역은 별도의 SafeArea를 유지합니다. easeOutCubic과 0~1로 제한한 이동량으로 패널이 최종 위치를 넘어서 튀어오르는 동작을 제거했습니다.

기존 퀴즈 하단 테스트에 24px 시스템 하단 여백을 설정하고, 패널 하단이 실제 화면 끝에 닿으면서 버튼은 안전 영역 위에 있는지 검사합니다. 정답·오답/기본·2배 글씨에서 애니메이션 프레임을 검사해 최종 높이보다 올라가지 않고 단조롭게 상승하는지 확인합니다. 전체 75개 테스트를 통과했습니다.
